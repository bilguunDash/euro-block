# Ээлжийн багаар хуваарь оноох — архитектур

**Огноо:** 2026-07-29 · **Төлөв:** ✅ хэрэгжсэн (build цэвэр, dev DB дээр e2e шалгасан)

Диаграм: [diagrams/shift-crew-architecture.mmd](diagrams/shift-crew-architecture.mmd)

## 1. Юуг яагаад өөрчилсөн

Өмнө нь хоёр газар хүндрэл байсан:

1. **Хяналтын бүтэц** (`control_assignments`) — оператор бүрт нэг мөр гараар оноодог
   хүн × хүн матриц. Ажилтан солигдох бүрт засах шаардлагатай.
2. **Ээлжийн хуваарь** — нэг хүнээр сонгож оноодог. 10 хүний баг = 10 удаагийн оноолт.

Хэрэглэгчийн хүсэлт: *«1-р ээлж гээд сонгоод тэр ээлжийн бүх хүн автоматаар орчихдог»*.

## 2. Гурван ойлголт

Хүн × хүн матрицыг гурван бие даасан зүйлээр орлуулав:

| # | Ойлголт | Хаана | Хэр олон удаа өөрчлөгдөх |
|---|---|---|---|
| 1 | **Ээлжийн баг** — `users.shiftGroup` (`1`/`2`/`3`/null) | DB багана + олноор засах UI | ажилтан баг сольсон үед |
| 2 | **Хүний станц** — `users.stationCode` | DB багана (өмнөөс байсан) | ажилтан станц сольсон үед |
| 3 | **Хариуцлагын дүрэм** — багийн мастер сонгох эрэмбэ | код (`lib/crew-master.ts`) | ховор |

Мастер ↔ оператор холбоо нь илэрхий мөр байхаа болиод **«ижил баг + ижил ээлж»** гэсэн
далд холбоо болов.

### Хариуцлага — багийн үндсэн (2026-07-29 шинэчилсэн)

**Багийн аль ч мастер тухайн багийн аль ч операторыг хариуцаж болно.**
«Станц → хариуцах мастер станц» гэсэн харьяалал БАЙХГҮЙ — холбоос нь зөвхөн
ижил баг дээр тогтоно.

Багт олон мастер байвал `lib/crew-master.ts` дараах дүрмээр сонгоно:

1. Тухайн өдөр/ээлжид **хуваарьтай** багийн мастерууд
2. Тэдгээрээс **ҮЯ-099 (Ээлжийн мастер)** тэргүүлнэ
3. Тэнцвэл нэрээр эрэмбэлж эхнийхийг авна
4. Хуваарьтай мастер огт байхгүй бол багийн бүх мастераас мөн адил дүрмээр

Ингэснээр үр дүн **давтагдана** (санамсаргүй биш).

## 3. Шинэ урсгал

| Үе шат | Хэн | Юу хийх |
|---|---|---|
| **A. Багийн бүрэлдэхүүн** | Админ | Ээлжийн хуваарь хуудасны «Багийн бүрэлдэхүүн» → checkbox-оор олноор сонгож «1-р ээлж болгох» |
| **B. Хуваарь оноох** | Админ | «Ээлжийн багаар оноох» → баг + огнооны муж + ээлжийн төрөл → нэг submit |
| **C. Ээлж ажиллах** | Систем | `findAssignedMasterForShift()` хариуцах мастерыг олж handover эхлүүлнэ |

## 4. Хариуцах мастер тодорхойлох

```
1. crew = операторын shiftGroup            → баггүй бол null
2. masters = тэр багийн бүх мастер          → байхгүй бол null
3. тухайн slot-д хуваарьтай мастерууд       → байвал зөвхөн тэднээс сонгоно
4. сонголт: ҮЯ-099 тэргүүлнэ → дараа нь нэрээр
```

Станц огт оролцохгүй. HTTP тестээр батлагдсан.

## 5. `control_assignments`-ийн үүрэг бүрийг юугаар орлуулсан

| # | Хуучин үүрэг | Шинэ шийдэл | Файл |
|---|---|---|---|
| 1 | Мастерын харах эрх | `crewOperatorUids()` — өөрийн багийн операторууд | `app/api/shifts/route.ts` |
| 2 | Ээлжийн хариуцах мастер | `resolveCrewMasterForShift()` | `lib/crew-master.ts` |
| 3 | Операторын хуваарь автоматаар үүсгэх | **Устсан** — багийн оноолт шууд бичнэ | `app/api/schedules/route.ts` |
| 4 | `users.stationCode` тавих | Хэрэглэгч засах модалд шууд | `app/api/users/route.ts` |
| 5 | Мастерын станц (`masterStationCode`) | `users.stationCode` | бүх газар |
| 6 | Хуваарийн хүснэгтийн багана | «Мастер дамжлага» → **«Ээлжийн баг»** болов | `CurrentScheduleTable.tsx` |

## 6. Кодын өөрчлөлт

**Шинэ:**

| Файл | Зориулалт |
|---|---|
| `lib/shift-crew.ts` | Багийн тогтмол, огнооны муж, гишүүн ялгах (client-safe) |
| `lib/crew-master.ts` | Хариуцах мастер сонгох + харах эрхийн хүрээ (server) |
| `app/api/users/shift-group/route.ts` | Багийн бүрэлдэхүүн олноор засах (admin) |
| `app/api/schedules/bulk-crew/route.ts` | Багийн хуваарь — **сервер тал, нэг transaction** |
| `app/api/stations/route.ts` | Станцын каталог (хуучин `/api/control-structure` GET) |
| `components/dashboard/admin/schedule/ShiftCrewAssignPanel.tsx` | Багаар оноох панел |
| `components/dashboard/admin/schedule/ShiftCrewManager.tsx` | Бүрэлдэхүүн засварлагч |
| `scripts/inspect-control-assignments.js` | Шилжилтийн өмнөх READ-ONLY аудит (7 шалгалт) |
| `scripts/backfill-master-station-code.js` | Мастеруудын `stationCode` нөхөх (`--apply`) |

**Устгасан:**

- `app/api/control-structure/route.ts` (assignment CRUD)
- `app/api/schedules/sync-operator/route.ts` (backfill хэрэггүй болсон)
- `AdminTab.tsx` дэх «Хяналтын бүтэц» карт
- `useDashboardAdmin.ts` дэх бүх control-assignment төлөв, handler
- `schedules/route.ts` дэх `findLinkedOperator`, `derivedOperatorTargets`,
  `syncDerivedOperatorSchedules`, `createOperatorScheduleIfMissing`

**Засвар:** `ҮЯ-400` нь `MASTER_STATION_CODES`-д байсан атлаа `isMasterStation = false`
гэж seed хийгддэг байсан — `true` болгов.

## 7. DB өөрчлөлт

```sql
-- 20260729000100_add_user_shift_group
ALTER TABLE "users" ADD COLUMN IF NOT EXISTS "shiftGroup" TEXT;
CREATE INDEX IF NOT EXISTS "users_shiftGroup_idx" ON "users" ("shiftGroup");
```

`control_assignments` **хүснэгт нь DB-д үлдсэн** — Prisma model `@deprecated` тэмдэгтэй,
код түүнийг уншихаа больсон. Шинэ систем тогтворжсоны дараа тусдаа migration-аар drop хийнэ.

> **Анхаар:** `prisma migrate dev` нь энэ repo-д ажиллахгүй — shadow DB replay нь хуучин
> `20260512000200_add_device_permissions` migration дээр унадаг (өмнөөс байсан асуудал).
> Migration-ыг гараар үүсгээд `prisma migrate resolve --applied <name>` хийсэн.

## 8. Prod deploy хийхээс өмнө

```powershell
cd C:\euroblock
node scripts\inspect-control-assignments.js > control-audit.txt 2>&1   # 1. одоогийн байдлыг хадгал
node scripts\backfill-master-station-code.js                            # 2. dry run
node scripts\backfill-master-station-code.js --apply                    # 3. бодитоор нөх
```

Дараа нь админ **багийн бүрэлдэхүүнийг оруулна** — `shiftGroup`-ыг одоо байгаа өгөгдлөөс
автоматаар гаргах боломжгүй, зөвхөн хэрэглэгч мэднэ. Үүнгүйгээр багаар оноох ажиллахгүй.

`inspect-control-assignments.js`-ийн **7-р шалгалтыг заавал хадгална** — шилжилтийн дараа
мастер бүрийн харах эрхийн хүрээ хэвээр эсэхийг харьцуулах суурь.
